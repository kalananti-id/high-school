Analisis Gaji Karyawan 💰

structure_analisis.py
# Level 1: Abstraksi (Detail)
def hitung_pajak(gaji_kotor):
  return gaji_kotor * 0.1

# Level 1: Abstraksi (Menggunakan Fungsi Lain)
def hitung_gaji_bersih(gaji_kotor):
  # Panggil fungsi lain (Komposisi)
  pajak = hitung_pajak(gaji_kotor)
  return gaji_kotor - pajak

# Level 0: Komposisi Utama
def proses_pembayaran(gaji):
  hasil = hitung_gaji_bersih(gaji)
  print(f"Gaji dibayar: {hasil}")

# Analisis dimulai dari sini:
proses_pembayaran(5000)

🔍 Langkah Analisis:

  1. Start di proses_pembayaran(5000).
  2. Masuk ke hitung_gaji_bersih.
  3. Masuk ke hitung_pajak. Hitung 5000 * 0.1 = 500.
  4. Kembali ke gaji_bersih. Hitung 5000 - 500 = 4500.
  5. Kembali ke proses. Print 4500.

Siklus Debugging (5 Tahap) 🔄

1

Reproduksi (Reproduce)

Pastikan error bisa diulang secara konsisten.

2

Lokalisasi (Localize)

Tentukan baris mana yang salah (Pakai Print/Breakpoint).

3

Diagnosis

Pahami KENAPA salah (Logic error? Variable salah?).

4

Perbaikan (Fix)

Ubah kode untuk memperbaiki bug.

5

Verifikasi (Verify)

Test ulang! Pastikan tidak ada bug baru (Regresi).

Alat Bedah: Debugger Interaktif 🛠️

Debugger memungkinkan kita menghentikan waktu dan melihat isi otak komputer.

🛑 Breakpoint

Titik henti. Program akan berjalan normal lalu PAUSE tepat di baris yang kamu tandai.

👣 Stepping (Langkah)

  • Step Over Lompati fungsi (Anggap selesai).
  • Step Into Masuk ke dalam detail fungsi.
  • Step Out Keluar cepat dari fungsi saat ini.

Mencegah Bug: Unit Testing 🛡️

Unit Testing adalah pengujian bagian terkecil (fungsi) untuk memastikan outputnya benar.

Konsep Dasar Test Case

Known Input
Input: 100
➜
Function
x * 2
➜
Expected Output
Harapan: 200
Jika Actual Output ≠ Expected Output, maka ada BUG! 🪲

Aktivitas: Bug Hunt 🕵️‍♀️

Kamu menerima kode, tetapi ada bug di dalamnya. Gunakan teknik Stepping dan Unit Test manual.
