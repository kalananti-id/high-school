Aplikasi Financial Literacy

Hari ini kita belajar bahwa aplikasi yang baik bukan cuma bisa dikoding, tapi juga harus menjawab masalah pengguna dengan jelas dan masuk akal.

User-Centric Problem Statement Python Logic App Blueprint

Pembuka: “Solusi yang Salah” 🤔

Pernah download aplikasi keuangan, tapi langsung dihapus karena terasa ribet, terlalu banyak istilah, atau tidak relate dengan kebutuhan kita?

“Banyak fitur” ≠ “Berguna”
“Bisa jalan” ≠ “Dipakai terus”
“Canggih” ≠ “Mudah dipahami”
Coding yang hebat percuma kalau tidak menjawab masalah pengguna.

Tujuan pembelajaran ✅

Membuat problem statement yang jelas
Merancang ide solusi berbasis kebutuhan pengguna
Menyusun flow aplikasi dari input ke output
Mengecek kelayakan fitur untuk dikoding dengan Python

Apa itu Design Thinking? 🧠

Design Thinking adalah pendekatan berpusat pada manusia untuk memecahkan masalah kompleks. Dalam pengembangan aplikasi, pendekatan ini membantu kita memastikan solusi teknis benar-benar menjawab kebutuhan pengguna.

Jadi, sebelum coding, kita perlu paham dulu: siapa penggunanya, apa masalahnya, dan solusi seperti apa yang relevan.

Tahap 3: Ideate — Brainstorming Solusi 💡

Ide solusi konten & pengalaman

Micro-learning untuk materi keuangan singkat dan mudah dicerna.
Gamification agar pencatatan pengeluaran terasa seperti challenge.
Visualisasi sederhana seperti pie chart atau bar chart.

Pertanyaan pemandu

• Fitur apa yang paling membantu pengguna memulai?
• Fitur mana yang membuat aplikasi terasa simpel?
• Fitur mana yang terlalu rumit untuk sesi proyek ini?
• Data apa yang perlu dicatat agar fitur bisa berjalan?

Tahap 4 & 5: Prototype + Test 🧩🧪

Prototype

  • Wireframe sederhana di kertas atau digital
  • Alur pengguna: input pemasukan → input pengeluaran → tampilkan saran
  • Fokus pada fungsi inti, bukan tampilan yang sempurna

Test

  • Uji kegunaan: mudah dipakai atau tidak?
  • Uji pemahaman: istilah dan instruksi jelas atau tidak?
  • Uji retensi: apakah pengguna mau terus memakai fiturnya?
Kalau hasil uji menunjukkan fitur budgeting belum menarik, kita kembali ke tahap Ideate untuk merancang solusi yang lebih cocok.

Latihan: Hubungkan Masalah dengan Konsep Coding 🧠

Lupa mencatat pengeluaran → pengingat setiap hari → Loop
Belanja melebihi budget → peringatan → Condition (if)
Ingin tahu total pengeluaran → penjumlahan transaksi → Variable
Ingin lihat kategori pengeluaran → pengelompokan data → List / Data

Diskusi cepat

Masalah apa yang paling dekat dengan kehidupan pelajar?
Konsep coding mana yang paling cocok untuk masalah itu?
Apakah solusi ini realistis untuk dibuat dengan Python dasar?

Cek Feasibility Fitur ✅

🟢
Mudah dibuat

Input pengeluaran, cek budget, hitung total, tampilkan pesan.

🟡
Bisa dicoba

Kategorisasi sederhana dengan daftar kata kunci atau aturan.

🔴
Terlalu kompleks

Machine learning penuh, sinkronisasi akun bank, atau AI prediksi rumit.

Untuk proyek akhir, pilih fitur yang berguna, jelas alurnya, dan masih realistis untuk dikoding.
